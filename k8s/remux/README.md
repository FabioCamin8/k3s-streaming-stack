# Remux workload

This directory contains the Kubernetes-native Remux workload for the existing
`streaming` namespace. It is intentionally one replica with one local-path
PVC, a ClusterIP Service, and the existing Traefik/cert-manager ingress. No
second runtime, database, cache service, or ingress controller is required.

## Upstream contract used here

The deployment is pinned to the stable `v0.27.0` release rather than the
mutable `latest` tag. The release was published on 2026-08-27 and provides
the `ghcr.io/lostb1t/remux` image for `linux/amd64` and `linux/arm64`.
Current upstream `main` was already ahead of that release on 2026-08-28, so
the release tag is the safer initial migration boundary. No automatic Remux
updates are enabled.

The detailed primary-source record is
[`docs/research/remux-current-contract-2026-08-28.md`](../../docs/research/remux-current-contract-2026-08-28.md).
The relevant upstream sources are the tagged [Dockerfile](https://github.com/lostb1t/remux/blob/v0.27.0/docker/Dockerfile),
[configuration](https://github.com/lostb1t/remux/blob/v0.27.0/crates/remux-server/src/lib.rs),
[database layer](https://github.com/lostb1t/remux/blob/v0.27.0/crates/remux-server/src/db/mod.rs),
[Jellyfin API](https://github.com/lostb1t/remux/blob/v0.27.0/crates/remux-server/src/api/),
and [release workflow](https://github.com/lostb1t/remux/blob/main/.github/workflows/release.yml).

| Property | Deployment contract |
| --- | --- |
| Image | `ghcr.io/lostb1t/remux:0.27.0` with `IfNotPresent` |
| Container port | 3000/TCP |
| Health | `GET /health`, a static HTTP 200 liveness endpoint |
| Durable root | `/data` |
| Database | SQLite `/data/db.sqlite`, WAL mode, migrations at startup |
| Torrent state | `/data/torrents` and `/data/cache` |
| Transcode state | `/data/transcode_sessions` when writable |
| Bundled web assets | `/app/jellyfin-web` and `/app/dashboard` (image filesystem) |
| Runtime user | Image does not declare a non-root `USER`; this manifest does not invent a UID/GID |
| FFmpeg | Image-provided Jellyfin FFmpeg at `/usr/lib/jellyfin-ffmpeg` |

The image also contains torrent and hardware-acceleration support. No host
devices, Docker socket, `hostNetwork`, privileged mode, or extra torrent
Service ports are enabled by this workload. Direct play avoids transcoding;
codec, subtitle, bitrate, and client profile choices can start an FFmpeg
transcode and therefore require materially more CPU and temporary storage.

## Apply and render

The `streaming` namespace is owned by the AIOStreams bundle. Render the ingress
hostname into a protected temporary directory:

```sh
REMUX_CONFIG_FILE=/secure/operator-secrets/remux.env \
  ./k8s/remux/render.sh /tmp/k3s-remux-manifests
kubectl kustomize /tmp/k3s-remux-manifests
kubectl apply -k /tmp/k3s-remux-manifests
```

The render output must stay outside Git because it contains the selected
hostname. cert-manager creates the TLS Secret in the cluster after the Ingress
is applied; that generated Secret is also outside Git. The operator's WAN
streaming forward is intentionally disabled while this stack is under
construction; local/LAN TLS validation uses the normal Traefik `websecure`
route and correct SNI instead.

Run the static checks before applying:

```sh
./scripts/verify/remux-render.sh
```

After applying the bundle, run `scripts/verify/remux.sh` with the operator's
Kubernetes context. Set `REMUX_URL` to the LAN-tested HTTPS origin and provide
`REMUX_API_TOKEN_FILE` for the authenticated addon contract check. An optional
`REMUX_LOCATION_CHECK_URL` can inspect a tested stream response; the verifier
fails if its `Location` header contains a cluster-local hostname.

## AIOStreams integration

Remux consumes AIOStreams as a Stremio addon configured through its admin API.
Use the configured, provider-free AIOStreams manifest URL, but replace its
public origin with the Kubernetes Service origin:

```text
http://aiostreams.streaming.svc.cluster.local/stremio/<configured-user-path>/manifest.json
```

The `<configured-user-path>` is generated by AIOStreams and contains private
configuration material; it must be supplied from a protected operator file,
never committed or printed. The helper uses Remux's admin API token and sends
the current `POST /addons` payload shape:

```sh
REMUX_CONFIG_FILE=/secure/operator-secrets/remux.env \
REMUX_API_TOKEN_FILE=/secure/operator-secrets/remux-api-token \
  ./k8s/remux/configure-aiostreams.sh
```

The helper refuses an addon URL outside the expected internal AIOStreams
Service and verifies `httpRedirectStream=false`. That setting is mandatory:
Remux proxies HTTP streams from this addon, so an internal source cannot be
returned to a client as a redirect. An external addon may independently use
`httpRedirectStream=true` only when its source URL is externally reachable.
The current upstream implementation makes this choice per addon, only for
HTTP direct-play sources, and returns a temporary HTTP 302 when enabled;
transcoding remains proxied.

## Route and trust-boundary inventory

- Public bootstrap: `/health`, `/system/info/public`, `/users/public`, and
  the incomplete startup wizard routes under `/startup/`.
- Jellyfin-native authentication: `POST /users/authenticatebyname` returns a
  session token; authenticated clients use `Authorization: MediaBrowser ...`
  or the supported Emby token headers.
- Authenticated client API: `/system/info`, `/users`, `/userviews`, `/items`,
  `/items/{id}/playbackinfo`, `/videos`, and `/sessions`.
- Streaming: `/videos/{id}/stream`, `/audio/{id}/stream`, and their container
  variants. HLS/transcode URLs remain under the Remux origin.
- Websocket: authenticated `/websocket` and `/socket`; Traefik's HTTP route
  preserves the WebSocket upgrade without a special middleware.
- Browser/admin: `/admin`, `/web`, and `/jellyfin` serve the bundled web
  clients; admin API handlers require the Remux admin session.

There is deliberately no blanket Traefik ForwardAuth. Selective Authelia for
human/admin paths is a later milestone; Jellyfin bootstrap, API, streaming,
and websocket behavior stays under Remux-native authentication.

## Persistence and recovery boundary

The PVC protects the complete `/data` tree: SQLite database and WAL files,
application data, torrent/rqbit state, cache metadata used by the torrent
manager, and transcode-session files when they are stored under the configured
data root. Container stdout/stderr remains the logging boundary; the upstream
server initializes logging to stdout in this image, so no unverified persistent
`LOG_FILE` setting is injected. A Deployment rollback is not an application-data backup. The K3s
datastore backup protects Kubernetes objects and Secrets but does not include
local-path PVC files. Off-node application backup and restore are not yet
implemented or claimed.

Remux runs migrations before it accepts requests. `/health` is a liveness
check, not a database-backed readiness check; the startup probe still covers
the migration window because the server does not listen until initialization
completes. Do not interrupt a first startup or upgrade. Pod recreation is the
required narrow recovery proof; a node reboot is optional after the
application-specific migration and persistence checks.
