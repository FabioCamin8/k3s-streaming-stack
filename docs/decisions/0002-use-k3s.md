# ADR-0002: K3s over kubeadm/full Kubernetes

- Status: Accepted
- Date: 2026-08-25

## Context

The stack needs Kubernetes APIs and primitives, but it begins as one node with limited operational budget. A full kubeadm-built cluster would add bootstrap and maintenance choices without improving the initial workload outcome.

## Decision

Use [K3s](https://docs.k3s.io/) as the Kubernetes distribution and use its bundled containerd, CoreDNS, Traefik, and local-path storage for v0.1.

## Consequences

Bootstrap is smaller and the platform remains Kubernetes-native. The initial cluster is intentionally single-node and uses node-local storage, so it does not provide high availability or storage redundancy.

## Alternatives considered

- kubeadm/full Kubernetes: more control, but more bootstrap and lifecycle work than this focused stack needs.
- MicroK8s: viable, but K3s better fits the desired small server distribution and bundled components.
- Docker Compose: simpler for one host, but it would not exercise the Kubernetes API and primitives this project is intended to document.
